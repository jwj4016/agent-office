# AI 활동과 업무 흐름 수정 UX 구현 계획

작성: 2026-10-20. 사용자 요청: 앞선 UX 검토를 바탕으로 계획과 구현을 진행하고 완료 항목을 체크한다.

## 재개 방법

이 문서 → `git diff` → 아래 첫 미완료 항목 순서로 확인한다. 기존 작업 파일을 되돌리지 않는다. 실제 AI 호출 없이 테스트 공급자로 검증한다. 완료 체크는 구현과 관련 검증을 마친 뒤 표시한다.

## 설계

- 기존 오른쪽 상세 패널을 공통 AI 활동 패널로 재사용한다. 서비스·실행·업무·담당자 맥락을 표시하고 대화·결정과 실행 로그를 구분한다.
- 실행 업무, 사무실 담당자, 서비스 현황에서 해당 활동을 연다. 질문은 기존 내 할 일에서 답변하고 메모는 다음 시도부터 반영됨을 유지한다.
- 과거 기록은 저장된 이벤트·메시지로 복원한다. 새로운 출력은 보존하며 기존에 저장되지 않은 출력은 복원했다고 표시하지 않는다. 비공개 추론은 수집하지 않는다.
- 업무 흐름 편집기 상단에서 AI 수정을 연다. 선택 업무/전체 범위, 요청 기록, 실제 수집된 진행 출력, 변경 전후 비교, 이전 제안에 대한 추가 수정 요청을 지원한다.
- 수정안은 명시적으로 초안에 적용한다. 저장하지 않은 변경과 오래된 수정안의 충돌을 막고 실행 중인 버전은 유지한다.
- 새 메시지는 읽는 위치를 유지하고 개수와 이동 버튼으로 안내한다. 키보드 닫기·초점 복원·좁은 화면을 지원한다.

## 진행 기록

- 시작: 기존 상세 패널, `RunMessages`, 실행 이벤트, `workflow_assists`를 우선 재사용한다. 사용자 기존 수정에 AI 연결 및 수정안 파싱·빈 검증 목록 처리가 포함되어 있으므로 보존한다.
- 기준선: 프론트 84개 통과. Go 저장·설계 테스트 통과. 엔진 전체 테스트는 Windows에 `true` 실행 파일이 없어 기존 `TestReviewPassMeetsCompletionCriteria/all_criteria_met` 1건 실패(변경 전에도 재현). 샌드박스 내 Go 빌드 캐시 접근 거부는 권한을 허용해 재실행했다.
- 화면 확인: 별도 QA 앱에서 서비스 현황 → AI 활동 → 대화/로그 전환 → 업무 선택·메모 저장, 업무 흐름 상단 → AI 수정 → 변경 전후 비교·캔버스 미리보기를 실제 DOM/접근성 트리로 확인했다. 자동 스크린샷은 브라우저 캡처 시간 초과로 실패했다. 비교에서 새 업무의 빈 고급 설정이 과도하게 보이는 문제를 발견해 숨기고 입력·결과·수정 대상을 읽기 쉬운 문구로 바꿨다.

## 검증·제한

- 프론트 전체 94개 통과 후 추가한 초점 복원 1건·보조 AI 응답 구분 1건은 해당 파일 재검증으로 통과(`ui.test.tsx` 5개, `AIActivity.test.tsx` 7개). 타입 검사·배포 빌드 통과. Vite의 기존 큰 청크 안내는 유지한다.
- 저장·설계·바인딩 테스트 통과. 신규 엔진 출력 보존·기존 회의 테스트 통과.
- Go 전체 회귀 실행: 엔진 이외 모든 패키지 통과. 엔진은 Git 하위 프로세스 실행 중 전체 10분 제한에 걸린 뒤 단독 재검증에서 469.5초에 통과했다. 기존 Windows `true` 명령 테스트만 제외했다(`-skip '^TestReviewPassMeetsCompletionCriteria$'`).
- 실제 앱 화면은 테스트용 데이터 폴더 `build/ai-activity-qa/data`와 명시적인 가짜 기록으로 검증했다. 운영 데이터와 원본 앱 인스턴스 설정은 변경하지 않았다. 검증용 앱·브라우저 탭은 종료했고 화면 크기 설정은 복원했다.
- 실제 UI 저장 확인: 메모가 `step:plan` 수신자로 저장됨, 수정안 적용으로 초안 수정 1→2·업무 0→2, 기존 실행의 확정 버전은 유지됨. `build/ai-activity-qa/validate.py` 읽기 전용 확인 통과.
- 좁은 창(실제 CSS 너비 888px): 패널 clientWidth=scrollWidth=388px로 가로 넘침 없음. Escape로 닫으면 ‘AI로 수정’ 버튼에 초점 복원. 캔버스 미리보기 동안 편집·저장·버전 확정 비활성화와 읽기 전용 목록 확인.
- 변경: 스키마 7은 수정 요청에 원본 초안·이전 요청·선택 업무를 추가한다. `AIActivity(projectId, runId, assistId, before)`는 한 서비스의 한 실행/수정 요청만 조회하고 이전 로그를 200개씩 읽는다. 요청 목록은 최근 200개, 화면에서 5개씩 추가 공개한다.
- 제한: 기존에 저장하지 않은 과거 스트리밍 출력은 복원하지 않는다. 새 출력은 1초/16KB 단위와 세션 종료 때 저장하므로 강제 프로세스 종료 직전의 미저장 배치는 유실될 수 있다. 모델의 비공개 추론은 수집하지 않는다.
- 제한: 실제 유료 AI 연결 재호출과 스크린샷 기반 시각 검증은 이번 작업에서 하지 않았다. 대화형 추가 수정은 이전 제안·요청을 전달하는 새 요청이며 진행 중인 업무에 즉시 메시지를 주입하지 않는다.
