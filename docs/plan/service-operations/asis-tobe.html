사건에 반응해 협업하는 작은 회사로

한 부서의 업무나 중간 자료가 다른 부서의 후속 작업으로 이어집니다. 필요한 부서만 참여하고, 공유한 자료와 사건을 근거로 각자 일을 진행합니다.

구현 전 계획입니다. 5차 개정: 직접 요청은 지정 부서에 전달하고, 일반 후속 사건은 구독으로 연결합니다. 실행 밖 AI 작업의 비용도 서비스 예산에 합산하고, 자동 모드에서는 AI가 참고용 협업 요청을 결정합니다. 이번 범위는 앱 안의 업무 관리이며, 실제 게시·광고 집행·배포와 앱 종료 후 상시 실행은 포함하지 않습니다.

구분현재개선 후
협업 연결처리 흐름에 참여 단계와 전달 관계를 설정새 업무·공유 자료·도움 요청 사건에 필요한 부서가 반응
직접 요청실행 안의 지정 담당자에게 질문·검토 요청구독이 꺼져 있어도 지정한 부서에 점검·협업 요청 전달
새 부서 추가기존 흐름에 역할과 단계를 배치책임과 구독을 설정하고 이후 사건부터 참여
중간 산출물실행의 정해진 후속 단계에 전달업무가 진행 중이어도 고정본을 공유하고 다른 부서가 참조
다음 할 일사람의 새 요청 또는 미리 연결한 단계구독 사건·협업 요청·정기 점검을 근거로 부서가 제안
자료 개정실행 안의 재작업과 영향 범위 관리다른 실행·부서의 사용 관계를 따라 재검토 후보 전달
완료 판단개별 실행의 완료 기준과 결과 검증책임자가 필수 협업 결과와 공동 목표의 해결 여부 확인
기존 워크플로주요 업무 실행 단위반복되는 작은 작업에 선택적으로 재사용

예시 · 마케팅의 A 업무와 B 업무는 협업 상대가 다를 수 있습니다

A 업무 — 캠페인 페이지: 기획안을 공유하면 개발팀이 구현 검토를 제안합니다. 비용 검토가 필요 없다면 재무팀은 대응 불필요로 남깁니다.

B 업무 — 광고 예산: 예산안을 공유하면 재무팀이 검토를 제안합니다. 개발할 내용이 없으면 개발팀은 새 업무를 만들지 않습니다.

자료 활용: 부서는 공유 자료함에서 필요한 초안을 찾아 자기 업무에 연결할 수도 있습니다. 자료를 읽는 행위 자체가 협업 업무를 자동 생성하지는 않습니다.

초안 개정: 1판을 사용한 업무는 그대로 기록합니다. 2판이 공유되면 관련 부서에 영향 확인을 요청하고 진행 중인 입력을 몰래 바꾸지 않습니다.

직접 요청: 마케팅팀이 개발팀을 지정해 협업을 요청하면 개발팀의 구독이 꺼져 있어도 전달합니다. 다른 부서에 같은 요청을 무조건 퍼뜨리지 않습니다.

확정: 초안을 내용 변경 없이 확정할 수 있습니다. 같은 파일·버전 번호를 유지하고 확정자와 시각을 기록합니다. 새 내용 버전은 다시 초안으로 시작합니다.

필수 협업: 요청이 거절되거나 수행 업무가 아직 없어도 필수 조건은 남습니다. 책임자가 이유를 남겨 해제하거나 대체한 뒤에야 완료 조건을 다시 판단합니다.

통제: 제안 검토와 자동 실행을 선택할 수 있습니다. 실패한 호출은 같은 판단 회차에서 재시도하고 질문 답변만 다음 회차로 넘어갑니다. 실패·중단·계획 생성 비용도 합산하며, 중복·무한 후속 업무는 전달 기록과 한도로 막습니다.
