## 2026-10-22 — 계획 검토 반영(3차)

- 검토에서 확인한 코드 사실:
  - `artifacts`는 `run_id`·`step_attempt_id`가 필수이고, 버전은 같은 실행의 단계·출력 키별로 매긴다. 작업 공간 파일 공유와 여러 실행에 걸친 문서 버전을 담을 수 없다.
  - 실행은 확정된 워크플로 버전이 있어야 시작된다.
  - `projectUsage`는 `step_attempt_id`가 있는 `provider.usage` 사건만 합산한다. 워크플로 AI 도우미(`design/assist.go`)처럼 실행 밖에서 호출한 비용은 예산에 잡히지 않는다.
  - 역할은 이미 상위 역할 계층과 지침을 가지고, 담당자 배정은 서비스별 AI 연결을 가진다.
  - 서비스에는 `mode`와 `auto_policy`가 이미 있다.
- 계획 변경:
  - 공유 문서·버전을 별도 테이블로 분리했다.
  - 부서 판단은 엔진 실행이 아닌 도우미 방식으로 처리하고, 사용량을 예산 집계에 합산한다.
  - 부서 = 회사 공통 + 역할 소속 + 서비스 부서(대표 담당자 배정)로 정의하고, 지침 계층에 `department` 층을 추가한다.
  - 사람이 한 명일 때 누가 결정하는지와 결정 횟수를 줄이는 방법을 명시했다.
  - 업무 실행 최소판을 3단계로 당겨 0~9단계로 재편했다.
  - 연쇄 깊이 기본값을 8에서 3으로, 연쇄당 자동 업무를 20에서 10으로 낮추고, 사건당 판단 부서 5개 상한을 추가했다.
  - 데이터 구조·사건 내용·기본 한도 부록(9장)을 추가했다.
  - 문서 사이의 예산 관련 모순(4.7절 ↔ 인수 항목)을 해소했다.
- 코드 변경: 없음. 계획과 진행 기록, 비교 시각화의 개정 표기만 수정.
- 기능 검증: 미실시.
- 다음 작업: 0단계의 남은 항목(최신 저장소 지침·변경 확인, 기존 테스트 실행, 업그레이드 원칙 확인)을 마치고 1단계를 구현한다.

## 2026-10-22 — 재검토 보완(4차)

- 직접 요청: 점검·협업 요청의 대상 부서를 별도 필드로 지정한다. 구독 필터와 무관하게 대상에게 직접 전달하고, 서비스·자료 접근·예산·권한 검사는 유지한다.
- 판단 복구: 논리 AI 작업, 질문 답변에 따른 회차, 실제 공급자 호출 시도를 구분한다. 실패·중단은 같은 회차의 새 시도로 처리하고 이미 저장한 결과는 재호출하지 않는다.
- 비용: 3단계부터 계획 생성과 판단이 같은 AI 작업·시도 구조를 사용한다. 실패·중단·재시도 사용량도 보존·합산하고 예산 보류 중에는 새 호출을 시작하지 않는다.
- 필수 협업: 수행 업무가 없어도 미수락·질문·거절·취소 상태의 필수 요청은 원본 업무와 공동 목표 완료를 막는다. 해제·대체에는 이유와 변경 기록을 남긴다.
- 문서 확정: 파일 내용 버전과 검토 상태를 구분한다. 같은 버전을 확정해도 파일·해시·번호를 바꾸지 않고 확정자·시각·사건 이력을 남긴다.
- 함께 갱신: 단계별 체크리스트, 인수 시나리오, 데이터 구조·사건 내용·기본 한도, 시각화 설명.
- 기준 설명 정정: 기존 산출물 버전은 시도별이 아니라 같은 실행의 단계·출력 키별로 매겨진다.
- 코드 변경: 없음. 기능 구현 완료 항목은 추가하지 않음.
- 검증: 보완한 다섯 항목을 본문·단계·인수 체크리스트·부록에 반영한 것을 확인함. 상대 링크, 0~9단계 순서, 세 파일의 4차 개정 표기, 한국어 표기·공백 형식 검사와 diagram-design의 `self_check.py`가 통과함. 미완료 체크리스트 102개와 문서 준비 완료 5개를 확인했으며 기능 완료 표시는 하지 않음.
- 미검증: 실제 앱 기능과 브라우저 화면. 이번 작업은 계획 보완이며 구현 시작 전 기준 테스트는 여전히 미완료다.
