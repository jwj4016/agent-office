# 서비스 운영 사용 안내 — 사건과 자료로 협업하는 작은 회사

서비스 하나를 작은 회사로 보고, 부서들이 서로의 일과 자료를 보고 필요한 일을 찾아 협업하는 기능입니다. 회사 전체에 고정된 업무 흐름을 그리지 않아도, 업무가 생기고 끝나거나 자료가 공유될 때마다 관련 부서가 할 일이 있는지 판단해 업무를 제안합니다. 설계와 단계별 기록은 [계획서](plan/service-operations/plan.md)와 [진행 기록](plan/service-operations/progress.md)에 있습니다.

## 기본 개념

| 용어 | 뜻 |
|---|---|
| 부서 | 서비스 안의 팀. 책임, 구성원(담당자), 대표 담당자를 가집니다. 판단과 협업 결정은 대표 담당자(AI)가 합니다. |
| 업무·공동 목표 | 업무는 한 부서가 맡은 일, 공동 목표는 여러 부서의 업무를 묶는 일입니다. 업무는 사람이 완료를 확인할 때까지 남습니다. |
| 사건 | 업무 생성·완료·다시 열기, 자료 공유·개정·확정·철회, 부서 점검 요청, 협업 요청처럼 다른 부서가 반응할 수 있는 일입니다. |
| 구독 | 부서가 어떤 사건(과 분류)을 보고 판단할지 정한 것. 판단 관점을 적으면 판단 지시에 그대로 들어갑니다. |
| 판단·제안 | 부서 대표 AI가 사건을 보고 ‘대응 불필요·업무 제안·추가 질문’ 중 하나로 답한 것. 제안은 사람이 등록해야 업무가 됩니다. |
| 협업 요청 | 한 업무가 다른 부서에 직접 도움을 청한 것. 참고용과 필수(완료 조건)가 있습니다. |
| 공유 자료 | 업무의 결과나 작업 폴더 파일을 판으로 공유한 것. 초안과 확정을 구분하고, 업무에 연결하면 그 판이 고정됩니다. |
| 정기 점검 | 부서가 매일·매주 정한 때에 새로 할 일이 있는지 살피는 것. |

## 사용 순서

1. **부서 만들기** — 서비스의 ‘부서·담당자’ 탭에서 부서를 만들고 구성원과 대표 담당자를 정합니다. 회사 조직의 부서 템플릿을 끌어다 놓아도 됩니다.
2. **판단 설정** — 부서 행의 ‘판단 설정’에서 받을 사건·분류·판단 관점을 구독으로 저장합니다. 같은 패널에서 정기 점검(매일·매주, 시각, 점검 관점)을 켜고, 그전에 공유된 자료는 ‘기존 자료 검토 요청’으로 검토시킵니다.
3. **업무와 공동 목표** — ‘업무’ 탭에서 공동 목표와 부서별 업무를 만듭니다. 업무의 ‘작업 계획과 실행’에서 담당자·지침·산출물을 정하거나 AI에게 계획을 제안받아 실행합니다. 확정한 업무 흐름 버전을 그대로 실행할 수도 있습니다.
4. **자료 공유** — 실행 결과나 작업 폴더 파일을 초안으로 공유하면 그 사건을 구독한 부서가 판단합니다. 다른 부서는 업무에 자료를 연결해 그 판을 입력으로 씁니다.
5. **협업 요청** — 업무의 ‘협업’에서 다른 부서에 요청합니다. 받는 부서(사람 또는 자동 모드의 대표 AI)가 수락하면 그 부서의 업무가 생깁니다. 필수 요청은 끝나야 원래 업무와 공동 목표를 완료할 수 있습니다.
6. **내 할 일 처리** — 결과 검토·협업·영향 확인·자동 처리·질문·제안을 공동 목표별로 모아 보여 줍니다. 위쪽 버튼으로 종류를 골라 볼 수 있고, ‘업무 열기’로 관련 업무로 갑니다.
7. **운영 확인** — 서비스 ‘현황’ 탭에서 부서별 진행 중 업무·결과 확인·막힘·기다리는 결정·전달 문제와 예산 보류, 비용을 알 수 없는 호출을 봅니다. 업무 상세의 ‘시작한 이유와 이어진 업무’에서 어떤 사건 때문에 이 부서가 이 업무를 시작했는지와 그 뒤 이어진 업무를 따라갈 수 있습니다.

## 검토 모드와 자동 모드

- 새 서비스와 새 부서는 검토 모드로 시작합니다. 제안 등록, 협업 수락, 계획 확인, 실행 시작은 사람이 합니다.
- 서비스가 자동 모드이고 서비스 자동 실행 허용 연결과 부서의 ‘자동화’ 규칙(분류·AI 연결·결과 형식·흐름 버전)을 모두 만족하면, 사건에서 생긴 업무를 AI가 계획하고 승인된 계획으로 실행하며 결과를 초안으로 공유할 수 있습니다. 맞지 않으면 ‘검토 필요’로 사람에게 넘어갑니다.
- 자동 모드에서도 필수 협업의 결정, 업무 완료, 자료 확정은 사람이 합니다. 대표 AI가 결정한 참고용 협업은 ‘AI 결정 확인’이나 ‘AI 결정 되돌리기’(이유 필요)로 확인합니다.
- 예산을 정하지 않은 서비스와 사람이 맡은 작업은 자동으로 시작하지 않습니다.

## 한도와 비용

| 항목 | 기본값 |
|---|---|
| 판단 1회당 업무 제안 | 5개 |
| 사건 1건당 구독 판단 부서 | 5개(직접 요청은 제외, 넘치면 보류) |
| 자동으로 이어지는 판단 깊이 | 3단계 |
| 연쇄 하나에서 자동 등록하는 업무 | 10개 |
| 같은 AI 작업의 자동 재시도 | 첫 호출 후 2회(사람이 다시 시도할 때마다 1회 추가) |
| 실행 밖 AI 호출 동시 처리 | 사용자 작업 1건 + 백그라운드 1건 |

- 판단·계획·협업 결정의 모든 호출 시도(실패·중단·재시도 포함) 사용량은 서비스 예산에 합산됩니다. 비용을 알려 주지 않는 연결의 호출은 0원이 아니라 ‘비용을 알 수 없는 AI 호출’로 셉니다.
- 예산이 보류되면 새 판단·계획·재시도·자동 실행을 시작하지 않습니다. ‘현황’ 탭에 이유가 보입니다.

## 알려진 제한

- AI가 협업 필요성을 판단하거나 제안하는 품질은 실제 AI로 체계적으로 시험하지 않았습니다. 자동 시험은 정해 둔 응답을 쓰는 시험용 공급자로 전달·재시도·중복 방지만 검증합니다.
- 앱에 들어 있는 ‘테스트 AI(가짜 응답)’ 연결은 정해진 형식으로 답하지 않으므로, 이 연결로는 판단·계획·협업 결정이 형식 오류로 실패합니다. 화면의 실패·재시도 흐름을 확인하는 데만 쓸 수 있습니다.
- 정기 점검 일정은 부서당 하나입니다. 같은 날 주기를 매일↔매주로 바꾸면 그날·그 주에 한 번 더 점검할 수 있습니다.
- 앱이 꺼져 있던 동안 놓친 정기 점검은 가장 최근 한 번만 합니다. 부서를 다시 ‘사용’으로 바꾸거나 서비스 보관을 풀면 그 사이 가장 최근 회차 하나가 실행될 수 있습니다.
- 한도 값(판단 부서 수, 연쇄 깊이, 연쇄당 자동 업무 수)은 아직 서비스 설정에서 바꿀 수 없고 기본값을 씁니다.
- 실행 중에 바뀌는 작업 폴더 파일을 계속 감시해 자동으로 공유하지 않습니다. 공유는 사람이 하거나 자동 실행이 끝났을 때 결과로 합니다.
- 운영 화면의 수치는 저장된 기록을 센 값뿐입니다. 성과·생산성 같은 추정 수치는 만들지 않습니다.
- Windows·Linux의 화면은 이 기능 범위에서 따로 확인하지 않았습니다(CI의 자동 시험만 통과).
