# UI/UX 전면 재설계 계획

기준 스킬: `ui-ux-pro-max` (우선순위 규칙 1→10, quick-reference), Anthropic `design` 플러그인(`design-critique`, `accessibility-review`, `ux-copy`)
범위: `frontend/` 전체. Go 바인딩·데이터 구조는 바꾸지 않습니다(다른 작업과 충돌 방지).

**규칙**
- 단계 안의 항목 1개씩: 구현 → `npm test`·`typecheck` 통과 → `[x]` 체크 → 다음 항목
- 단계가 끝나면 실제 앱(`wails dev`)에서 화면을 확인하고 단계 제목에 ✅ 표시
- 기존 테스트가 화면 구조 변경으로 깨지면 의도(무엇을 보장하는가)를 유지한 채 새 구조에 맞게 고침

## 1. 진단 요약 (2026-10-18)

| 문제 | 근거 |
|---|---|
| 막힌 실행의 **원인과 다음 행동이 보이지 않음** | 실행 '막힘·실패'인데 사유 표시 없음, 첫 업무가 사유 없이 '취소됨' |
| 서비스 첫 화면(사무실)이 **상태를 숨김** | 실패한 실행이 있어도 모두 평소처럼 앉아 있음 |
| 정보 구조가 기능 단위로 흩어짐 | '전체 서비스'는 카드만, 할 일·막힘·진행이 한눈에 모이지 않음 |
| 시각 위계 약함 | 모든 버튼·배지가 같은 무게, 아이콘 없음, 12px 회색 설명문 과다 |
| 대비 미달 4건 | 보조 글자 4.17~4.34:1, 오류 글자 4.46:1, 입력 테두리 1.32:1 |
| 편집기 가독성 | 업무 14개를 화면에 맞추면 글자를 읽을 수 없음 |
| 개발자 말투 문구 | "캐릭터 동작은 표시일 뿐 상태를 정하지 않습니다", "비용 미보고" 등 |

잘 된 점(유지): 삭제 2단계 확인, 빈 상태 안내, 모션 줄이기, 모든 입력란 이름표, 탭 role, 키보드로 사무실 탐색.

## 2. 설계 원칙

1. **상태 우선** — 어느 화면이든 "지금 무엇이 막혔고 내가 무엇을 해야 하는가"가 맨 위에 온다.
2. **한 화면 한 주 행동** — 화면마다 primary 버튼은 하나, 나머지는 보조·고스트.
3. **점진적 공개** — 고급 설정(예산, 검증 명령, 제한, 분기)은 접어 두고 필요할 때 연다.
4. **색만으로 말하지 않기** — 모든 상태는 아이콘 + 글자 + 색.
5. **AI는 보라, 사람은 살구** — 기존 정체성을 유지하는 의미 색.
6. **사무실은 상징, 현황은 도구** — 픽셀 사무실은 남기되 일은 현황 화면에서 한다.

## 3. 디자인 시스템 (ui-ux-pro-max 적용 결과)

자동 생성안(랜딩 패턴, Google Fonts Inter, 청록 팔레트)은 데스크톱·오프라인·기존 정체성에 맞지 않아 채택하지 않고, 아래 규칙만 반영합니다.

| 영역 | 결정 | 스킬 근거 |
|---|---|---|
| 스타일 | Minimalism & Swiss + 업무용 밀도(Data-Dense 일부) | style: Minimalism & Swiss Style, data-dense-dashboard |
| 색 | 따뜻한 중성 바탕 + 단일 primary(보라) + 의미 색 4종(성공·주의·위험·정보), 라이트/다크 토큰 | color-semantic, color-dark-mode, color-accessible-pairs |
| 대비 | 본문·보조 글자 ≥4.5:1, 입력 테두리·아이콘 ≥3:1 (스크립트로 검증) | color-contrast, non-text contrast |
| 글꼴 | Pretendard(로컬 번들, 인터넷 불필요) → 시스템 글꼴 대체 | font-loading, 한국어 가독성 |
| 글자 크기 | 12 / 13 / 14(본문) / 16 / 20 / 24, 최소 12px, 줄 간격 1.5 | font-scale, readable-font-size |
| 간격 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 | spacing-scale |
| 모서리·그림자 | 6 / 8 / 12px, 그림자 3단계 | elevation-consistent |
| 아이콘 | lucide-react 한 벌, 선 굵기 1.75, 16/20px | no-emoji-icons, icon-style-consistent |
| 모션 | 120 / 180 / 240ms, ease-out, transform·opacity만, 모션 줄이기 존중 | duration-timing, reduced-motion |
| 상호작용 | 포인터 대상 ≥24px(주요 버튼 32px), hover·pressed·disabled 상태 구분 | web-target-size, state-clarity |
| 피드백 | 저장·처리 결과는 토스트(aria-live polite, 4초), 오류는 해당 위치 + role=alert, 오류에는 다음 행동 | toast-accessibility, error-recovery |
| 내비게이션 | 왼쪽 사이드바(아이콘+글자), 현재 위치 강조, 화면 전환 시 본문 제목으로 포커스, 본문 바로가기 | nav-label-icon, focus-on-route-change, skip-links |

## 4. 새 정보 구조

```
사이드바                         서비스 화면 탭
─────────────                    ──────────────────────────────
[+ 새 목표]  ← primary            현황(기본) · 사무실 · 실행 · 업무 흐름 · 담당자 · 설정
홈  (지금 상황)
내 할 일 (n)                     실행 상세
─ 서비스 ─                       ┌ 상태 머리말: 진행 막대 · 주 행동
● VillaLens  (상태 점+글자)       ├ 주의 필요: 막힌 업무 · 원인 · [다시 시도]
                                 ├ 업무 타임라인 (아이콘 상태)
회사 조직                         └ 대화·결정
설정
```

- **홈**: 내 할 일 · 막힌 실행 · 진행 중 실행을 서비스 구분 없이 모아 보여 주고, 아래에 서비스 카드.
- **새 목표**(기존 '목표 요청'): 사이드바 맨 위 주 버튼. 3단계 입력(목표 → 맡을 일·방식 → AI 연결)으로 나눔.
- **서비스 '설정' 탭**: 기존 '개요'의 이름·목표·지침·폴더·모드·예산·자동 범위·내보내기·보관을 묶음.
