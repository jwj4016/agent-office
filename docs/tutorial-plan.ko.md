# 첫 실행 튜토리얼 구현 계획

작성: 2026-10-20. 앱 첫 실행 안내와 사용자가 다시 열 수 있는 튜토리얼 버튼을 추가한다.

## 재개 방법

이 문서 → 현재 `git diff` → 첫 미완료 항목 순서로 확인한다. 기존 AI 활동 기능과 다른 작업의 변경은 유지한다.

## 동작

- 설정을 불러온 뒤 아직 안내를 닫거나 끝낸 기록이 없으면 튜토리얼을 자동으로 연다. 완료·건너뛰기·Escape로 닫았는지를 기존 앱 설정에 저장한다.
- 사이드바의 ‘튜토리얼’ 버튼으로 첫 단계부터 다시 연다. 작업 화면·입력·실행에는 영향을 주지 않는다.
- 앱 개요 → AI 연결 → 새 목표 → 업무 흐름 수정·실행 → 진행·내 할 일·결과 확인을 짧은 5단계로 안내한다. 실제 AI 호출이나 예제 실행은 자동으로 하지 않는다.
- 이전·다음·건너뛰기·완료를 지원한다. 네이티브 dialog로 초점을 관리하고 닫으면 원래 위치로 돌려준다. 작은 창·다크 모드·키보드를 지원한다.
- 확인 상태 저장 실패는 토스트로 알리고 앱 사용은 계속할 수 있게 한다. 성능 측정 실행에서는 자동 안내를 생략한다.

- [x] 4. 최초 실행·재실행·닫기·저장 실패 테스트와 타입 검사·빌드
- [x] 5. 검증 결과와 재개 정보를 계획·진행 문서에 기록

## 검증 기록

- `npm test -- --reporter=dot`: 22개 파일, 102개 테스트 통과. 자동 표시·다음 실행 시 생략·수동 재실행·입력 유지·초점 복원·5단계 이동·완료·Escape·저장 실패·느린 설정 응답·성능 측정 모드 포함.
- `npm run build`: 타입 검사와 Vite 배포 빌드 통과. 기존 500KB 이상 청크 안내는 유지.
- `go test . -run TestFrontendSettingKeysAreAllowed -count=1 -timeout=2m`: 통과. `ui.tutorialSeen`을 기존 설정 저장 허용 목록에 추가했으며 새 스키마나 바인딩은 필요 없다.
- 변경 파일의 `git diff --check` 통과.
- 실제 앱 창의 화면·다크 모드·키보드 포커스 가두기는 이번 작업에서 수동 검증하지 않았다. 네이티브 dialog와 기존 색상 토큰을 사용했으며 자동 테스트는 jsdom에서 초점 이동·복원과 취소 이벤트를 확인한다.

필수 구현 완료. 실제 앱에서 추가 확인할 때는 새 데이터 폴더로 최초 안내를 보고, 닫은 뒤 재시작하여 생략되는지 확인한다. 기존 데이터도 안내 확인 기록이 없으면 업데이트 후 한 번 표시된다. 왼쪽 ‘튜토리얼’ 버튼으로 모든 단계를 다시 볼 수 있다.
